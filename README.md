# ⛵ אפליקציית מועדון שייט (Sailing Club App & PWA)

אפליקציית מובייל-פירסט (PWA) ייעודית למועדוני שייט, המחליפה את קבוצות הוואטסאפ בניהול מסודר של הפלגות מועדון, הרשמות ותורי המתנה אוטומטיים, פיד קהילתי, גלריית תמונות, ופאנל ניהול חברים מלא.

---

## 🌟 יכולות עיקריות

1. **ניהול הפלגות, לוח שנה ומערכת קרדיטים**:
   - **לוח שנה חודשי אינטראקטיבי** המציג את כל מועדי ההפלגות, זמני יציאה וסטטוס.
   - **הפלגת מועדון (Club Sail):**
     - מינימום 3 משתתפים לסגירה ויציאה, מקסימום 6 משתתפים.
     - יורד בדיוק 1 קרדיט לכל משתתף שנרשם (מוחזר אוטומטית בעת ביטול).
     - חיווי ברור: "ממתין לחברים נוספים" לעומת "יציאה מובטחת".
   - **הפלגה פרטית (Private Sail):**
     - מינימום 3 שעות (עלות: 3 קרדיטים), ו-1 קרדיט נוסף לכל שעה נוספת (למשל 4 שעות = 4 קרדיטים).
     - מנוכה מחשבון החבר המזמין בעת הפתיחה.
   - **רשימת המתנה אוטומטית:** כשההפלגה מלאה, חברים נרשמים להמתנה (#1, #2...). בעת ביטול, הראשון עולה ומחויב בהתאם.

2. **ניהול צי כלי שייט ולוח דיווח תקלות**:
   - הגדרת שמות סירות, דגמים, קיבולת ומיקומי רציף.
   - סטטוס סירה חי: **זמין להפלגה** / **בהספנה ותיקון** / **לא זמין**.
   - דיווח תקלות ע״י חברים עם קטגוריות וחומרה (התקלה מוצגת בלוח מודעות פומבי לכלל החברים והמנהלים).

3. **משתמשים, אבטחה ואיפוס סיסמה**:
   - אימות והרשמה עם מייל וסיסמה מורכבת (לפחות 8 תווים, שילוב אותיות ומספרים).
   - מנגנון איפוס/שחזור סיסמה באמצעות קישור וקוד אימות במייל.
   - חברים חדשים נכנסים למצב **"ממתין לאישור" (Pending)** עד לאישור מנהל.
   - עדכון רמת הסמכה של משיטים (משיט 60, משיט 30, משיט 40, איש צוות וכו').
   - מחיקת משתמשים עם הגנה מפני מחיקת המנהל האחרון.
   - אפשרות איפוס מסד נתונים נקי לחלוטין (Clean Database).

4. **פיד קהילה ושיתוף**:
   - פרסום עדכונים וחוויות.
   - דחיסת תמונות אוטומטית במכשיר (Client-side) לפני ההעלאה לחיסכון בנפח וברוחב פס.
   - תצוגה מקדימה עשירה של קישורים (Open Graph).
   - נעיצת הודעות חשובות בראש הפיד ע״י מנהל, לייקים ותגובות.

5. **PWA והתראות Push**:
   - התקנה למסך הבית של כל סמארטפון (iOS Safari / Android Chrome) בלי חנויות אפליקציות.
   - תמיכה בהתראות Web Push על הפלגות חדשות, ביטולים, ועלייה מהמתנה.
   - פעילות במצב לא מקוון (Offline).

6. **פאנל ניהול (Admin Panel)**:
   - אישור או דחייה של חברים חדשים בלחיצה.
   - ניהול תפקידי חברים (קידום למנהל / הורדה לחבר).
   - הגדרות מועדון (שם, מקסימום משתתפים, חלון ביטול).
   - סטטיסטיקה ודירוג החברים הפעילים ביותר.

## 📍 מצב נוכחי של הפרויקט

האפליקציה פועלת בשני מצבים, שנבחרים אוטומטית לפי משתני הסביבה:

| מצב | מתי | איפה הנתונים |
|------|------|------|
| **Supabase** (ייצור) | `VITE_SUPABASE_URL` ו-`VITE_SUPABASE_ANON_KEY` מוגדרים | בסיס נתונים משותף בענן, התחברות אמיתית, עדכונים חיים בין מכשירים |
| **הדגמה** (Demo) | המשתנים לא מוגדרים | `localStorage` בדפדפן בלבד, כל מכשיר רואה רק את הנתונים של עצמו |

| רכיב | מצב |
|------|------|
| ממשק משתמש (כל המסכים) | ✅ קיים |
| לוגיקה עסקית (קרדיטים, המתנה, הרשאות) | ✅ קיים + טסטים |
| PWA (התקנה למסך הבית, Offline) | ✅ קיים |
| סכמת בסיס נתונים + RLS + פונקציות שרת (`schema.sql`) | ✅ קיים + טסטים |
| חיבור ל-Supabase (נתונים משותפים, Auth, Realtime) | ✅ קוד מוכן, ממתין לבדיקה על פרויקט אמיתי |
| מיילים אמיתיים (אימות הרשמה, איפוס סיסמה) | ✅ דרך Supabase Auth |
| שמירת תמונות ב-Supabase Storage | ⏳ כרגע תמונות דחוסות נשמרות בתוך בסיס הנתונים |
| התראות Push בין מכשירים | ⏳ שלב 3 |
| פריסה ל-Vercel | ⏳ שלב 3 |

### ארכיטקטורה בקצרה
- `src/services/dataStore.ts` – הממשק המשותף לשכבת הנתונים.
- `src/services/localStore.ts` – מצב הדגמה (localStorage).
- `src/services/supabaseStore.ts` – מצב Supabase. קריאות מוגשות מתמונת מצב בזיכרון; כל כתיבה נשלחת לשרת ואחריה התמונה נטענת מחדש. מנוי Realtime מרענן אותה כשמכשיר אחר משנה משהו.
- `schema.sql` – כל פעולה שנוגעת בנתונים של משתמש אחר (קרדיטים, רשימת המתנה, התראות, אישור חברים) מתבצעת בפונקציות שרת מאובטחות (RPC). הדפדפן לא יכול לשנות לעצמו קרדיטים, תפקיד או סטטוס.

## 🛠️ פיתוח מקומי

דרישות: [Bun](https://bun.sh) (או Node.js 20+).

```bash
bun install        # התקנת תלויות
bun run dev        # שרת פיתוח בכתובת http://localhost:3000
bun run lint       # בדיקת טיפוסים (TypeScript)
bun run test       # כל הבדיקות: לוגיקה עסקית + סכמת בסיס הנתונים
bun run test:db    # רק בדיקות הסכמה (Postgres מקומי בזיכרון באמצעות PGlite, לא נדרש Supabase)
bun run build      # בניית גרסת פרודקשן לתיקייה dist/
```

לעבודה מול Supabase מקומית: העתק את `.env.example` ל-`.env.local` ומלא את הערכים (הקובץ לא נשמר ב-git).

## 🚀 מדריך התקנה ופריסה (צעד-אחר-צעד למי שאינו מפתח)

### שלב 1: הקמת פרויקט ב-Supabase
1. היכנס ל-[supabase.com](https://supabase.com) והירשם בחינם.
2. לחץ על **New Project**, תן שם לפרויקט (למשל `sailing-club`), בחר סיסמה לבסיס הנתונים ואזור קרוב (למשל Frankfurt).
3. בתפריט הצדדי לחץ על **SQL Editor** ואז על **New Query**.
4. העתק את **כל** תוכן הקובץ `schema.sql`, הדבק ולחץ **Run**. (יש להריץ פעם אחת בלבד, על פרויקט ריק.)
5. עבור ל-**Project Settings → API** ושמור את `Project URL` ואת `anon public key`.

### שלב 2: הגדרות התחברות ומיילים (Authentication)
1. **Authentication → URL Configuration**:
   - **Site URL**: כתובת האפליקציה (למשל `https://sailing-club.vercel.app`; לפיתוח מקומי `http://localhost:3000`).
   - **Redirect URLs**: הוסף את אותה כתובת (וגם `http://localhost:3000` לפיתוח).
2. **Authentication → Sign In / Providers → Email**: מומלץ להשאיר את **Confirm email** פעיל. חבר חדש יקבל מייל אימות, ואחריו ימתין לאישור מנהל.
3. **Authentication → Emails → Reset Password**: כדי שהמייל יכלול גם קוד בן 6 ספרות (בנוסף לקישור), הוסף לתבנית את השורה:
   ```html
   <p>קוד האיפוס שלך: <strong>{{ .Token }}</strong></p>
   ```
4. **שימו לב:** שירות המיילים המובנה של Supabase מוגבל למספר קטן של מיילים בשעה. לשימוש אמיתי במועדון מומלץ לחבר שירות SMTP (למשל Resend או Brevo) תחת **Authentication → Emails → SMTP Settings**.

### שלב 3: המנהל הראשון
- **המשתמש הראשון שנרשם הופך אוטומטית למנהל מאושר** (עם 20 קרדיטים). לכן הירשם ראשון בעצמך מיד אחרי ההתקנה.
- כל מי שנרשם אחריו נכנס למצב "ממתין לאישור" עד שמנהל מאשר אותו בפאנל הניהול.

### שלב 4: פריסה לענן ב-Vercel
1. היכנס ל-[vercel.com](https://vercel.com) ולחץ על **Add New... → Project**.
2. ייבא את המאגר מ-GitHub.
3. בהגדרות **Environment Variables** הוסף:
   - `VITE_SUPABASE_URL` = ה-Project URL מ-Supabase
   - `VITE_SUPABASE_ANON_KEY` = ה-anon public key מ-Supabase
4. לחץ **Deploy**. בסיום עדכן את ה-Site URL ב-Supabase (שלב 2) לכתובת שקיבלת.

### שלב 5: התקנה על הטלפון (PWA)
1. פתח את הקישור שקיבלת מ-Vercel בדפדפן בטלפון.
2. **באייפון (iOS Safari):** לחץ על כפתור השיתוף (מרובע עם חץ למעלה) ובחר **"הוסף למסך הבית"**.
3. **באנדרואיד (Chrome):** לחץ על הבאנר "התקן עכשיו", או דרך שלוש הנקודות בתפריט → "התקן אפליקציה".
